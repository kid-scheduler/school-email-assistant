# 0001: Use a Documentation-First Public Repository

## Status

Accepted

## Context

The project is intended to be public and understandable on its own. It should not depend on private local history or unpublished implementation details.

## Decision

Start with a documentation-first repository that captures requirements, architecture, workflows, open questions, harness guidance, and blog-aligned planning before application implementation begins.

## Consequences

- Public readers can understand the project direction before code exists.
- Future agents have durable context in Markdown.
- Implementation work has a clearer product and safety boundary.
- Some early effort goes into docs before runnable software.
