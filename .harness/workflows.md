# Harness Workflows

## Requirements Work

1. Update product requirements and open questions.
2. Use role-based review for user, product, privacy, calendar safety, and implementation concerns.
3. Record refined decisions in product docs.
4. Update blog drafts or outline when the public narrative changes.

## Spec Work

1. Explore ambiguity before proposing behavior.
2. Create OpenSpec proposal, design, specs, and task list.
3. Review before implementation.
4. Keep durable product/architecture docs in sync.

## UI Mock Work

1. Define scenario and fixture data.
2. Build static HTML mock.
3. Add semantic selectors for important states and actions.
4. Get human design review.
5. Use accepted mock as implementation contract.

## Implementation Work

1. Read `AGENTS.md`.
2. Read only the deeper docs needed for the task.
3. Make scoped changes.
4. Run deterministic checks.
5. Update docs, decisions, and current state when needed.
6. Summarize verification and remaining risks.
